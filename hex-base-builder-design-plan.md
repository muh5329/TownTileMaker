# Hex Card Base-Builder — Godot Design & Technical Plan

## 1. Core Concept

A single starting hex tile sits at the center of an isometric 3D world. The player holds a
**hand of cards**, each representing a tile type (resource producer, wall, turret, housing,
etc.). Playing a card places a new hex tile adjacent to the existing base, snapped to the hex
grid. Resources generated by tiles fund more cards; **Strength** represents the base's combat
power against incoming enemy waves. The camera behaves like a classic RTS: pan, rotate, zoom,
free look around the base.

This doc breaks the game into independent systems, gives each a Godot implementation approach,
and ends with a build-order roadmap so you can implement it incrementally in engine.

---

## 2. Core Gameplay Loop

1. Player has a **hand** of N cards (drawn from a deck/pool).
2. Player selects a card → game shows **valid placement hexes** (empty neighbors of any
   already-placed tile) highlighted around the current base.
3. Player clicks a highlighted hex → tile is placed, card is spent, resources/strength update.
4. Tiles passively generate resources over time (production tick).
5. Enemy waves spawn periodically and path toward the base; tiles' **Strength** and any
   defense-type tiles (walls, turrets) determine how much damage the base absorbs/deals.
6. New cards are drawn to refill the hand (draw pile / cooldown / resource-cost draw — pick one,
   see §4.4).
7. Loop continues; difficulty scales, player expands the hex footprint outward.

## 3. Hex Grid System

### 3.1 Coordinate system
Use **axial coordinates** `(q, r)` internally (simplest for storage/lookup), convert to **cube
coordinates** `(x, y, z)` only when you need distance/range/line calculations (pathfinding,
line-of-sight, AoE).

```gdscript
# HexMath.gd  (autoload or static class_name utility)
class_name HexMath

const HEX_SIZE := 1.0 # world-space "radius" of one hex, tune to your mesh

# Axial -> world position (pointy-top hexes, good for isometric readability)
static func axial_to_world(q: int, r: int) -> Vector3:
	var x = HEX_SIZE * (sqrt(3.0) * q + sqrt(3.0) / 2.0 * r)
	var z = HEX_SIZE * (1.5 * r)
	return Vector3(x, 0.0, z)

# World -> nearest axial (for click/raycast placement)
static func world_to_axial(pos: Vector3) -> Vector2i:
	var q = (sqrt(3.0)/3.0 * pos.x - 1.0/3.0 * pos.z) / HEX_SIZE
	var r = (2.0/3.0 * pos.z) / HEX_SIZE
	return _cube_round(q, r)

const AXIAL_DIRS := [
	Vector2i(1, 0), Vector2i(1, -1), Vector2i(0, -1),
	Vector2i(-1, 0), Vector2i(-1, 1), Vector2i(0, 1)
]

static func neighbors(cell: Vector2i) -> Array[Vector2i]:
	var out: Array[Vector2i] = []
	for d in AXIAL_DIRS:
		out.append(cell + d)
	return out

static func _cube_round(qf: float, rf: float) -> Vector2i:
	var xf = qf
	var zf = rf
	var yf = -xf - zf
	var x = round(xf); var y = round(yf); var z = round(zf)
	var dx = abs(x - xf); var dy = abs(y - yf); var dz = abs(z - zf)
	if dx > dy and dx > dz: x = -y - z
	elif dy > dz: y = -x - z
	return Vector2i(int(x), int(z))
```

### 3.2 Grid data model
An autoload singleton owns the authoritative map state:

```gdscript
# HexGridManager.gd (autoload)
extends Node

var placed_tiles: Dictionary = {}   # Vector2i -> TileInstance (node/data ref)

func is_occupied(cell: Vector2i) -> bool:
	return placed_tiles.has(cell)

func get_valid_placement_cells() -> Array[Vector2i]:
	var valid := {}
	for cell in placed_tiles.keys():
		for n in HexMath.neighbors(cell):
			if not is_occupied(n):
				valid[n] = true
	return valid.keys()

func place_tile(cell: Vector2i, tile_node: Node3D) -> void:
	placed_tiles[cell] = tile_node
	tile_node.position = HexMath.axial_to_world(cell.x, cell.y)
```

Starting state: seed `placed_tiles` with the center tile at `Vector2i(0,0)` in `_ready()`.

### 3.3 3D isometric presentation
- Model each tile as a hex prism (flat-top mesh, ~0.2–0.4 units tall) with a swappable "surface"
  mesh/material per card type (grass, quarry, wall, turret base, etc.).
- Camera uses a fixed pitch (~30–45°) orthographic-style projection for a classic iso look —
  either a true `Camera3D` with `projection = ORTHOGONAL`, or perspective with a long distance +
  narrow FOV to minimize parallax. Orthogonal is simpler and reads more "strategy game."

## 4. Card System

### 4.1 Card data (Resource-driven, data-only — no logic in the resource itself)

```gdscript
# CardData.gd
extends Resource
class_name CardData

@export var id: StringName
@export var display_name: String
@export var description: String
@export var icon: Texture2D
@export_enum("Resource", "Wall", "Turret", "Housing", "Special") var card_type: String
@export var tile_scene: PackedScene       # what gets instanced on the grid
@export var resource_cost: Dictionary = {}  # {"wood": 10, "stone": 5}
@export var strength_value: int = 0         # contribution to base Strength stat
@export var resource_yield: Dictionary = {} # {"wood": 2} per production tick, if applicable
```

Every concrete card is a `.tres` resource file built from this class — fast to author/balance in
the editor with zero code changes, and easy to expand later (add fields without touching logic).

### 4.2 Deck / Hand manager

```gdscript
# CardManager.gd (autoload)
extends Node
signal hand_changed
signal card_selected(card: CardData)
signal card_deselected

var deck: Array[CardData] = []
var hand: Array[CardData] = []
var hand_size := 5
var selected_card: CardData = null

func draw_to_full_hand() -> void:
	while hand.size() < hand_size and deck.size() > 0:
		hand.append(deck.pop_front())
	hand_changed.emit()

func select_card(card: CardData) -> void:
	selected_card = card
	card_selected.emit(card)

func deselect() -> void:
	selected_card = null
	card_deselected.emit()

func spend_selected_card() -> void:
	hand.erase(selected_card)
	deselect()
	hand_changed.emit()
	draw_to_full_hand() # or on a timer/cost — see 4.4
```

### 4.3 UI: hand + resource/strength bar
- `CanvasLayer` → `HandUI` (HBoxContainer of `CardButton` scenes) bound to
  `CardManager.hand_changed`.
- Each `CardButton`: icon, name, cost chips, strength badge; `pressed` → `CardManager.select_card()`.
- Top bar `CanvasLayer` → `StatsUI`: resource counters bound to `ResourceManager` signals, and a
  Strength total bound to `HexGridManager`/`ResourceManager`.
- Selected-card visual state: highlight border on the selected `CardButton`, cursor changes to a
  ghost icon.

### 4.4 Refill/cost model (pick one, it changes pacing a lot)
- **Free refill**: hand refills immediately after playing a card — fastest pace, resource cost is
  the only brake.
- **Timed refill**: new card every X seconds regardless of hand plays — encourages patience/planning.
- **Draw-for-resources**: spend a resource to draw an extra card — resources gate both building
  *and* options, more strategic tension.

Recommend starting with **free refill + resource cost gating** for a first playable version; it's
the simplest to implement and tune.

## 5. Placement System (the "snappy" part)

### 5.1 Flow
1. `CardManager.card_selected` fires → `PlacementController` asks `HexGridManager` for
   `get_valid_placement_cells()`.
2. For each valid cell, spawn a lightweight **highlight marker** (a flat hex outline mesh with
   an emissive/transparent shader) at `HexMath.axial_to_world(cell)`.
3. Raycast from mouse each frame (`Camera3D.project_ray_origin/normal` against a ground plane or
   the highlight markers' collision shapes) to detect hover; tint the hovered marker differently
   (e.g., valid = cyan, hovered-valid = green, would-be-invalid = red — though invalid cells
   simply aren't shown at all, so you mostly need valid/hover states).
4. On click over a valid highlighted cell: instance `card.tile_scene`, call
   `HexGridManager.place_tile(cell, instance)`, deduct `resource_cost` via `ResourceManager`,
   call `CardManager.spend_selected_card()`, clear highlights.
5. Right-click / Esc while a card is selected → `CardManager.deselect()`, clear highlights.

```gdscript
# PlacementController.gd
extends Node3D

var active_markers: Array[Node3D] = []
const HIGHLIGHT_SCENE := preload("res://scenes/placement_highlight.tscn")

func _ready():
    CardManager.card_selected.connect(_on_card_selected)
    CardManager.card_deselected.connect(_clear_highlights)

func _on_card_selected(_card: CardData) -> void:
    _clear_highlights()
    for cell in HexGridManager.get_valid_placement_cells():
        var marker := HIGHLIGHT_SCENE.instantiate()
        add_child(marker)
        marker.position = HexMath.axial_to_world(cell.x, cell.y)
        marker.set_meta("cell", cell)
        marker.clicked.connect(_on_marker_clicked.bind(marker))
        active_markers.append(marker)

func _on_marker_clicked(marker: Node3D) -> void:
    var cell: Vector2i = marker.get_meta("cell")
    var card := CardManager.selected_card
    if not ResourceManager.can_afford(card.resource_cost):
        return # TODO: play "denied" feedback
    var tile := card.tile_scene.instantiate()
    HexGridManager.place_tile(cell, tile)
    get_tree().current_scene.add_child(tile) # or a dedicated TileContainer node
    ResourceManager.spend(card.resource_cost)
    CardManager.spend_selected_card()
    _clear_highlights()

func _clear_highlights() -> void:
    for m in active_markers:
        m.queue_free()
    active_markers.clear()
```

### 5.2 "Snappy" feel checklist
- Highlight markers appear **instantly** on card select (no tween delay); a subtle scale-in
  (0.08–0.12s) reads as responsive without feeling laggy.
- Tile placement itself can have a small juice pass: quick scale/drop-in tween + a placement
  sound, but keep it under ~150ms so it never feels like it's blocking the next action.
- Use `Area3D`/`CollisionShape3D` per marker for precise picking rather than only raycasting to a
  ground plane + math — clicking the actual hex shape feels more accurate than a distance check.

## 6. Resources & Strength

```gdscript
# ResourceManager.gd (autoload)
extends Node
signal resources_changed(resources: Dictionary)
signal strength_changed(total: int)

var resources: Dictionary = {"wood": 20, "stone": 10, "food": 10}
var total_strength: int = 0

func can_afford(cost: Dictionary) -> bool:
	for k in cost:
		if resources.get(k, 0) < cost[k]:
			return false
	return true

func spend(cost: Dictionary) -> void:
	for k in cost:
		resources[k] -= cost[k]
	resources_changed.emit(resources)

func add(yield_dict: Dictionary) -> void:
	for k in yield_dict:
		resources[k] = resources.get(k, 0) + yield_dict[k]
	resources_changed.emit(resources)

func recalc_strength() -> void:
	var total := 0
	for tile in HexGridManager.placed_tiles.values():
		total += tile.get("strength_value") if tile.has_method("get") else 0
	total_strength = total
	strength_changed.emit(total_strength)
```

Production tick (put on a `Timer` autoload node or in `ResourceManager._process` with an
accumulator): iterate placed tiles, sum `resource_yield` from any tile that produces, call
`ResourceManager.add()`.

## 7. RTS Camera Controller

```gdscript
# RTSCamera.gd — attach to a Node3D rig; Camera3D is a child positioned via SpringArm3D
extends Node3D
class_name RTSCamera

@export var pan_speed := 20.0
@export var edge_pan_margin := 12.0   # pixels from screen edge to trigger edge-scroll
@export var zoom_speed := 3.0
@export var min_zoom := 6.0
@export var max_zoom := 35.0
@export var rotate_speed := 100.0     # degrees/sec

@onready var spring_arm: SpringArm3D = $SpringArm3D

func _process(delta: float) -> void:
	_handle_pan(delta)
	_handle_rotate(delta)
	_handle_zoom(delta)

func _handle_pan(delta: float) -> void:
	var dir := Vector3.ZERO
	if Input.is_action_pressed("cam_forward"): dir.z -= 1
	if Input.is_action_pressed("cam_back"): dir.z += 1
	if Input.is_action_pressed("cam_left"): dir.x -= 1
	if Input.is_action_pressed("cam_right"): dir.x += 1

	# optional edge-of-screen panning
	var mouse := get_viewport().get_mouse_position()
	var vp := get_viewport().get_visible_rect().size
	if mouse.x < edge_pan_margin: dir.x -= 1
	elif mouse.x > vp.x - edge_pan_margin: dir.x += 1
	if mouse.y < edge_pan_margin: dir.z -= 1
	elif mouse.y > vp.y - edge_pan_margin: dir.z += 1

	if dir != Vector3.ZERO:
		# move relative to current yaw so "forward" always means "up the screen"
		translate(dir.normalized().rotated(Vector3.UP, rotation.y) * pan_speed * delta)

func _handle_rotate(delta: float) -> void:
	var input := Input.get_axis("cam_rotate_left", "cam_rotate_right")
	rotate_y(deg_to_rad(rotate_speed * delta * -input))

func _handle_zoom(delta: float) -> void:
	var input := Input.get_axis("cam_zoom_in", "cam_zoom_out")
	spring_arm.spring_length = clamp(
		spring_arm.spring_length + input * zoom_speed,
		min_zoom, max_zoom
	)
```

Bind `cam_forward/back/left/right` to WASD, `cam_rotate_left/right` to Q/E, zoom to the mouse
wheel axis, and (optionally) middle-mouse-drag pan for a more traditional RTS feel. Keep the
`SpringArm3D`'s pitch fixed (locked rotation on X) to preserve the isometric read even while
rotating around Y.

## 8. Enemies / Waves

- `WaveManager` autoload/node: `Timer`-driven wave spawner, spawns enemy scenes at points outside
  the current base radius (derive spawn ring from the bounding radius of `placed_tiles`).
- Enemies use Godot's `NavigationAgent3D` (bake a `NavigationRegion3D` around the play area, or —
  since movement is hex-grid-relative — do simple straight-line-to-nearest-tile movement, which
  is often enough for this genre) to approach the nearest placed tile.
- On contact: enemy deals damage to that tile's HP; tiles with `strength_value` reduce incoming
  damage or return damage (design choice — simplest: total base Strength = a global damage-output
  stat used in an abstracted "combat resolution" each wave rather than per-tile HP, which is much
  less to implement for a first pass).
- **Recommended for v1**: abstract combat — each wave has a power rating; base's `total_strength`
  is compared against it; shortfall removes/damages a random non-core tile or drains resources.
  This avoids full combat/pathfinding/animation work until the core loop is proven fun.

## 9. Scene & Autoload Architecture

```
Autoloads (singletons):
  HexGridManager     - grid state, placement queries
  ResourceManager     - resources + strength totals
  CardManager        - deck/hand/selection
  WaveManager        - enemy spawning/combat resolution

Main.tscn
├── World (Node3D)
│   ├── CameraRig (RTSCamera.gd)
│   │   └── SpringArm3D
│   │       └── Camera3D
│   ├── TileContainer (Node3D)        # placed hex tile instances live here
│   ├── PlacementController (Node3D)  # highlight markers, click handling
│   ├── EnemyContainer (Node3D)
│   └── GroundPlane / NavigationRegion3D
└── UI (CanvasLayer)
	├── StatsBar (resources + strength display)
	├── HandUI (card row)
	└── (pause/build menus etc.)
```

### Tile scene contract
Every `tile_scene` referenced by a `CardData` should be a small scene with a root script
implementing a shared interface, e.g. `TileBase.gd`:

```gdscript
class_name TileBase
extends Node3D

@export var strength_value: int = 0
@export var resource_yield: Dictionary = {}
var grid_cell: Vector2i
```

This keeps `HexGridManager`/`ResourceManager` able to treat every placed tile uniformly
regardless of visual type.

## 11. Build-Order Roadmap

**Phase 1 — Grid & Camera (no cards yet)**
- `HexMath`, `HexGridManager`, place the single center tile.
- `RTSCamera` with pan/zoom/rotate.
- Click a hex → print its axial coords (proves raycast + math).

**Phase 2 — Placement loop**
- `PlacementController` + highlight markers around the single starting tile.
- Hardcode one tile type; click a highlight → place it → highlights recompute around the new
  larger base.

**Phase 3 — Cards & Resources**
- `CardData` resource class, author 3–5 `.tres` cards.
- `CardManager` hand + `HandUI`.
- Wire card selection → `PlacementController`; wire placement → `ResourceManager.spend`.
- `StatsBar` UI bound to resource/strength signals.

**Phase 4 — Production tick**
- Timer-based resource generation from placed tiles; visible counters ticking up.

**Phase 5 — Waves (abstracted combat first)**
- `WaveManager` timer, simple power-rating vs. `total_strength` resolution, visible
  win/lose feedback per wave.

**Phase 6 — Polish pass**
- Placement/selection juice (tweens, sounds), card art, tile meshes/materials, camera edge-pan,
  UI polish, balancing pass on costs/yields/strength numbers.

**Phase 7 (stretch) — Real combat**
- Per-tile HP, enemy pathfinding via `NavigationAgent3D`, projectile/attack animations for
  turret-type tiles.

## 12. Open Design Questions to Resolve Early
- **Refill model** (§4.4) — pick before building `CardManager`, it affects UI and pacing.
- **Combat model** (§8) — abstracted vs. per-tile HP; strongly recommend abstracted for v1.
- **Map bound** — is the hex field infinite, or capped at a radius (simpler collision/AI logic,
  clearer difficulty curve as space runs out)?
- **Card rarity/variety** — flat pool vs. weighted draw vs. unlockable card types over a run.
